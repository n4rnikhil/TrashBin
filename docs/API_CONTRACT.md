## 1. Conventions

| Topic | Rule |
|---|---|
| Format | JSON (`application/json`), except multipart upload and content streaming. |
| Identifiers | UUID strings. |
| Timestamps | ISO-8601 UTC, e.g. `2026-11-15T10:15:30Z`. Dates: `YYYY-MM-DD`. |
| Naming | `camelCase` JSON properties. |
| Unknown properties | Ignored on input; never echoed. |
| Authentication | `Authorization: Bearer <accessToken>` unless the endpoint is marked *public* or *ticket*. |
| Ownership | A resource that exists but belongs to someone else returns **404**, identical to a missing one. |
| Concurrency | Mutable resources return an `ETag` (`"<version>"`). `PATCH` requires `If-Match`; mismatch → `412`. |
| Pagination | `page` (0-based, default 0), `size` (default 25, max 100). Response is `PageResponse<T>` (below). |
| Sorting | `sort=<field>,<asc\|desc>` with a per-endpoint **whitelist**; other fields → `400`. |
| Rate limiting | Auth endpoints throttled per client IP (default 10 requests/minute); `429` with `Retry-After`. |
| Cookie endpoints | `/auth/refresh` and `/auth/logout` require header `X-Requested-With: trashbin` and an allowed `Origin`. |

```jsonc
// PageResponse<T>
{ "content": [ /* T */ ], "page": 0, "size": 25, "totalElements": 132, "totalPages": 6 }
```

## 3. Details

### 3.1 Upload — `POST /files`

`multipart/form-data` with two parts:

| Part | Type | Notes |
|---|---|---|
| `file` | binary | Required. Exactly one file per request. |
| `metadata` | `application/json` | Optional. See below. |

```jsonc
// metadata
{
  "displayName": "Tax return 2019",        // optional, ≤ 255; defaults to the filename
  "notes": "Scanned copy",                  // optional, ≤ 10000
  "contextNote": "Keep until audit window closes", // optional, ≤ 2000
  "originDate": "2020-04-15",               // optional
  "tags": ["tax", "2019"],                  // optional, ≤ 20
  "collectionIds": [],                      // optional; must be owned
  "allowDuplicate": false                   // default false
}
```

A duplicate (same owner and SHA-256, any status) with `allowDuplicate=false` returns:

```jsonc
// 409
{
  "type": "https://trashbin.local/problems/duplicate-file",
  "title": "Duplicate file",
  "status": 409,
  "code": "DUPLICATE_FILE",
  "traceId": "4f1c…",
  "existing": { "id": "…", "displayName": "Tax return 2019", "status": "DISCARDED" }
}
```

Multiple files are uploaded as multiple requests (the client queues them).

### 3.2 List and search — `GET /files`

| Param | Type | Notes |
|---|---|---|
| `q` | string ≤ 200 | Full-text query (`websearch_to_tsquery` semantics). Ranked when present. |
| `status` | `ARCHIVED` \| `DISCARDED` | Default `ARCHIVED`. |
| `tag` | repeatable UUID | AND semantics. |
| `collection` | UUID | |
| `typeGroup` | enum | `IMAGE DOCUMENT SPREADSHEET PRESENTATION TEXT AUDIO VIDEO ARCHIVE OTHER` |
| `favorite` | boolean | |
| `from`, `to` | date | Range over `archivedAt`. |
| `sort` | whitelist | `archivedAt`, `displayName`, `sizeBytes`, `lastAccessedAt`; `relevance` only with `q`. Default `archivedAt,desc`. |
| `page`, `size` | int | See conventions. |

### 3.3 Content — `GET /content/{ticket}`

- Authentication is the signed ticket (HMAC-SHA-256, separate key): `{userId, fileId, purpose, exp}`.
  Lifetimes: **DOWNLOAD 60 s, PREVIEW 5 min** (viewers issue range requests while open).
- The server also verifies the file still exists and is owned by the ticket's user. Files in either
  status (`ARCHIVED` or `DISCARDED`) may be downloaded or previewed; purged files no longer exist. A
  ticket is never authorization on its own.
- Supports `Range` (206 / 416) and `ETag`/`If-None-Match`.
- Response headers:

| Case | Headers |
|---|---|
| `DOWNLOAD` (any type) | `Content-Type: application/octet-stream`, `Content-Disposition: attachment; filename*=UTF-8''<sanitized>` |
| `PREVIEW` image / text (non-SVG, non-HTML) | `Content-Type: <detected>`, `Content-Disposition: inline; filename*=…` |
| `PREVIEW` PDF | as above; CSP strategy pending ([ADR-001 §6](DECISIONS/ADR-001-architecture.md#6-open-items)) |
| all | `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cache-Control: private, no-store`, `Content-Security-Policy` (see SECURITY_GUIDELINES §7), `Content-Length` |

Previewable allowlist: `image/png`, `image/jpeg`, `image/gif`, `image/webp`, `text/plain`, and
`application/pdf` **once the PDF strategy is decided** (until then PDFs are `attachment` only and
`previewable=false`). SVG, HTML, and everything else are `attachment` only.

## 4. Error model

All errors are RFC 9457 `application/problem+json`:

```jsonc
{
  "type": "https://trashbin.local/problems/validation-failed",
  "title": "Validation failed",
  "status": 400,
  "code": "VALIDATION_FAILED",        // stable, machine-readable
  "detail": "One or more fields are invalid.",
  "traceId": "4f1c9a…",               // matches the server log entry
  "errors": [ { "field": "email", "message": "must be a well-formed email address" } ]
}
```

`errors` appears only for validation failures. Messages never contain stack traces, SQL, file system
paths, or secrets.

| `code` | HTTP | Meaning |
|---|---|---|
| `VALIDATION_FAILED` | 400 | Invalid body, parameter or sort field. |
| `UNAUTHENTICATED` | 401 | Missing/invalid/expired access token. |
| `INVALID_CREDENTIALS` | 401 | Wrong email/password, **or** account locked (indistinguishable by design). |
| `INVALID_REFRESH_TOKEN` | 401 | Unknown, expired, revoked or reused refresh token. |
| `FORBIDDEN` | 403 | Authenticated but lacks the role (e.g., admin endpoints) or missing cookie-endpoint headers. |
| `REGISTRATION_DISABLED` | 403 | Registration turned off by configuration. |
| `TICKET_INVALID` | 403 | Ticket malformed, expired, wrong purpose, or target gone. |
| `NOT_FOUND` | 404 | Missing **or not owned**. |
| `EMAIL_ALREADY_REGISTERED` | 409 | Registration conflict (accepted enumeration risk; see SECURITY_GUIDELINES §11). |
| `DUPLICATE_FILE` | 409 | Same SHA-256 already archived. |
| `INVALID_STATE_TRANSITION` | 409 | e.g., purge of an `ARCHIVED` file; discard of an already `DISCARDED` file. |
| `VERSION_CONFLICT` | 412 | `If-Match` does not match current version. |
| `PRECONDITION_REQUIRED` | 428 | An edit was sent without `If-Match`. |
| `TAG_ALREADY_EXISTS` | 409 | A tag with this name (case-insensitive) already exists. |
| `FILE_TOO_LARGE` | 413 | Over the size limit. |
| `QUOTA_EXCEEDED` | 413 | Would exceed the user's quota. |
| `UNSUPPORTED_MEDIA_TYPE` | 415 | Blocked by policy/denylist, or preview not available for the type. |
| `FILE_SIGNATURE_MISMATCH` | 422 | Bytes contradict the extension/declared type for a signature-checked format. |
| `TOO_MANY_REQUESTS` | 429 | Throttled; `Retry-After` set. |
| `INTERNAL_ERROR` | 500 | Unexpected failure; generic message plus `traceId`. |

## 5. DTO shapes

Request and response DTOs are immutable Java records; entities are never serialized. Representative
shapes (full schemas live in the OpenAPI snapshot). Example values are fictional. Fields are added in the
milestone that implements them: `tags` and `favorite` are live since M3a; `collections`, `previewable`
and `extractionStatus` are not part of the responses yet. Upload metadata accepts `tags` (M3a);
`collectionIds` arrives with M3b. `GET /files` accepts `favorite=true|false` since M3a.

```jsonc
// RegisterRequest
{ "email": "user@example.com", "displayName": "Sam", "password": "<min 12 chars, max 72 bytes>" }
// LoginRequest
{ "email": "user@example.com", "password": "<password>" }
// AuthResponse   (refresh token is delivered only as an HttpOnly cookie, never in the body)
{ "accessToken": "<jwt>", "expiresIn": 600, "user": { /* UserProfile */ } }
// UserProfile
{ "id": "…", "email": "user@example.com", "displayName": "Sam", "role": "USER" }
// FileSummary
{ "id": "…", "displayName": "Tax return 2019", "mediaType": "application/pdf", "typeGroup": "DOCUMENT",
  "sizeBytes": 482113, "status": "ARCHIVED", "favorite": false, "previewable": true,
  "tags": [ { "id": "…", "name": "tax", "color": "#3366CC" } ],
  "archivedAt": "2026-11-15T10:15:30Z", "originDate": "2020-04-15", "extractionStatus": "DONE" }
// FileDetail = FileSummary +
{ "originalFilename": "scan_0042.pdf", "sha256": "<64 hex>", "notes": "…", "contextNote": "…",
  "collections": [ { "id": "…", "name": "Taxes" } ], "discardedAt": null, "purgeAfter": null,
  "lastAccessedAt": null, "updatedAt": "…", "version": 3 }
// AccessTicket
{ "url": "/api/v1/content/<ticket>", "expiresAt": "2026-11-15T10:16:30Z" }
// IntegrityResult
{ "ok": true, "expectedSha256": "<64 hex>", "actualSha256": "<64 hex>", "verifiedAt": "…" }
// Stats
{ "archivedCount": 120, "discardedCount": 4, "usedBytes": 91234567, "quotaBytes": 5368709120 }
```

Never present in any response: `storageKey`, `ownerId`, `passwordHash`, refresh tokens, other users' data.

## 6. Compatibility policy

- The API is versioned in the path. Within `v1`, only **additive** changes are allowed (new optional
  fields, new endpoints). Removing or changing a field's meaning requires `v2` or an ADR.
- The OpenAPI snapshot test fails when the generated spec differs from the committed file, forcing
  contract changes to be deliberate and reviewed.
